# Алгоритмы аналитического ядра

## 1. Расчёт пульсовых зон (шкала Olympiatoppen)

### Зоны интенсивности
| Зона | % от ЧССmax | Лактат ммоль/л |
|------|-------------|----------------|
| Z1   | 60–72%      | < 1.5          |
| Z2   | 73–82%      | 1.5–2.5        |
| Z3   | 83–87%      | 2.5–4.0        |
| Z4   | 88–91%      | 4.0–8.0        |
| Z5   | 92–100%     | > 8.0          |

### Логика расчёта
1. Если в physiological_markers есть max_hr (source='measured') → использовать его
2. Иначе → ЧССmax = 220 - возраст, пометить source='formula'
3. Границы зон = процент * ЧССmax
4. Если есть threshold_hr (source='measured') → скорректировать границу Z3/Z4:
   верхняя граница Z3 = threshold_hr, нижняя граница Z4 = threshold_hr

## 2. Адаптация группового шаблона

### Формула
T_ind = T_template * k_qual * k_form

### Коэффициент квалификации k_qual
| Квалификация        | k_qual |
|---------------------|--------|
| Без разряда         | 0.70   |
| III–II разряд       | 0.85   |
| I разряд            | 1.00   |
| КМС                 | 1.10   |
| МС и выше           | 1.20   |

### Коэффициент формы k_form (по TSB)
| TSB               | k_form |
|-------------------|--------|
| TSB > 5           | 1.05   |
| -10 ≤ TSB ≤ 5     | 1.00   |
| -25 ≤ TSB < -10   | 0.90   |
| TSB < -25         | 0.75   |

### Логика
1. Для каждого атлета группы — извлечь актуальные маркеры
2. Если маркеров нет — использовать расчётные, установить флаг 'требует проверки'
3. Рассчитать зоны ЧСС по алгоритму 1
4. Получить TSB из training_load_history (последняя запись)
5. Применить формулу масштабирования
6. Проверить T_ind на методические ограничения зоны
7. Рассчитать прогнозный TSS
8. Сохранить individual_workout (status='draft', marker_id_used=текущий маркер)

## 3. Расчёт индексов нагрузки

### TSS одной тренировки
IF = avg_hr / threshold_hr
TSS = (duration_min * IF² * 100) / 60

### Накопленные индексы (обновлять после каждой тренировки)
ATL_n = ATL_(n-1) + (TSS_day - ATL_(n-1)) / 7
CTL_n = CTL_(n-1) + (TSS_day - CTL_(n-1)) / 42
TSB_n = CTL_(n-1) - ATL_(n-1)

### Начальные значения
При отсутствии предыдущей записи: ATL=0, CTL=0

### Прогнозный TSS (для черновиков)
Использовать среднюю точку целевого ЧСС-диапазона зоны вместо avg_hr

## 4. Генерация диагностических алертов

### Правила перегрузки (группа П)
| Код | Условие | Severity |
|-----|---------|----------|
| П1  | TSB < -30 три и более дней подряд | critical |
| П2  | ЧСС покоя > 7% от 14-дневной нормы | warning |
| П3  | Средний HRV за 7д < 85% от базового | warning |
| П4  | Усталость >= 4 И сон <= 2 три дня подряд | warning |
| П5  | Доля Z4+Z5 за неделю > 20% | info |

### Правила недогруза (группа Н)
| Код | Условие | Severity |
|-----|---------|----------|
| Н1  | Изменение CTL за 14д < 2 единиц (не восст. период) | info |
| Н2  | TSB > 15 семь и более дней подряд | info |
| Н3  | TSS за неделю < 50% от среднего за 8 недель | warning |
| Н4  | ЧСС покоя снижается > 5% за 30д И срабатывает Н1 | info |
| Н5  | Доля Z1+Z2 за 4 недели < 75% | info |

### Настраиваемые пороги (хранить в конфиге)
Все числовые пороги вынести в settings, чтобы тренер мог их менять.

### Логика запуска
Алерты генерируются при трёх триггерах:
1. После сохранения новой actual_telemetry
2. После сохранения новых subjective_metrics
3. После обновления training_load_history
